Ghidra for Bun: the pyghidra API surface, a Bun plugin (`?ghidra`, `ghidra:`), a script context for translated GhidraScripts, and a native `onBeforeParse` plugin (Rust, `system/ghidra-bun`). Bun only, no npm dependency.

- Full API: a headless Ghidra JVM (official release) driven through `bridge/Bridge.java` (reflection JSON-RPC over stdio). Any Ghidra class/method is reachable by name; every call is `async`.
- Fast path: `aphrody-re` (Rust) through the NAPI addon, no JVM.
- Requirements for the JVM backend: JDK 25 (Ghidra 12.2) and `GHIDRA_INSTALL_DIR` (or `~/.config/ghidra/lastrun`). `scripts/provision-fr2.sh` shows the fr2 setup (`/srv/ghidra-release`).
- Parity with pyghidra: `PARITY.md` (generated by `scripts/parity/run.ts` on fr2).

## API (pyghidra names in camelCase)

```ts
import * as ghidra from "@aphrody/ghidra";
await ghidra.start();                                    // pyghidra.start()
await using h = await ghidra.openProgram("./a.exe", { analyze: true });  // open_program (with)
const fm = await h.program.getFunctionManager();
for (const f of await (await fm.getFunctions(true)).$list()) console.log(await f.getName());
const addr = await h.flat.toAddr(0x401000);
const c = await ghidra.decompile(h.program, await h.flat.getFunctionAt(addr));
await ghidra.transaction(h.program, "edit", async () => { await h.flat.setEOLComment(addr, "x"); });
```

Main exports of `@aphrody/ghidra` (the index also re-exports `createFlat`, `sprintf`, `getContext`, ... from `flat.ts` and `context.ts`): `start started stop openProgram withProgram openProject openFilesystem consumeProgram programContext analyze ghidraScript transaction analysisProperties programInfo programLoader taskMonitor walkProject walkPrograms runScript getCurrentInterpreter debugCallback ApplicationInfo ExtensionDetails ProgramTypeError HeadlessPyGhidraLauncher DeferredPyGhidraLauncher GuiPyGhidraLauncher jvm Session`, plus helpers `summarize listFunctions decompile decompiler`.

Java objects are `JObject` proxies: `await obj.method(args)` calls the Java method; `$str() $list() $field(n) $setField(n,v) $instanceOf(c) $release()`; `await obj.toString()` is Java `toString`. Classes: `jvm().cls("ghidra.program.model.listing.Program")` for statics (`await C.$field("ANALYSIS_PROPERTIES")`, `await C.new_(...)` for constructors, or `jvm().newObject(cls, ...args)`). Java arrays/Iterables: `await x.$list()`. `bigint` is sent as long, `Uint8Array` as `byte[]`, `Session.array("java.lang.String", [...])` for typed arrays.

## Python context managers

`with pyghidra.open_program(...) as flat:` becomes `await using h = await openProgram(...)` or `withProgram(path, opts, async (h) => ...)`; `with transaction(p, d)` becomes `transaction(p, d, async () => ...)`; `with program_context(project, path) as p` becomes `programContext(project, path, async (p) => ...)`.

## Script context: `@aphrody/ghidra/script` (target of py2bun)

GhidraScript / FlatProgramAPI globals. The full list is in `src/flat.ts` (`FLAT_PROGRAM_API`, `GHIDRA_SCRIPT_EXTRA`, `SCRIPT_FIELDS`) and `src/script.generated.ts` (193 async functions, regenerate with `bun scripts/gen-script-exports.ts`).

```ts
import { currentProgram, currentAddress, monitor, toAddr, getFunctionAt, getFunctions, println, askString } from "@aphrody/ghidra/script";
const f = await getFunctionAt(currentAddress);
await println(`${await currentProgram.getName()} ${await f?.getName()}`);
```

- Fields (`currentProgram currentAddress currentLocation currentSelection currentHighlight monitor state sourceFile`) are live bindings, set by `runScript(binary, script)`, `setContext(ctx)` or the CLI `bun-ghidra script <bin> <script.ts>`. `runScript` fills `currentLocation`, `currentSelection`, `currentHighlight` and `state` with `null` (headless: no GUI selection) and `sourceFile` with the script path.
- Every function is async (Promise); translated code must `await` them. `println/print/printerr/printf/popup` run locally; `ask*` take answers from `GHIDRA_ASK_<NAME>` (e.g. `GHIDRA_ASK_STRING`) or reject with `CancelledException` (headless semantics); `askYesNo` defaults to true; `isRunningHeadless()` is true.
- `getScriptArgs()` returns `runScript(..., { scriptArgs })`.

## Bun plugin

```toml
# bunfig.toml
preload = ["@aphrody/ghidra/preload"]
```

```ts
import analysis, { functions } from "./a.exe?ghidra";        // JVM backend (full Ghidra)
import fast from "./a.exe?ghidra=native";                    // aphrody-re addon (GHIDRA_BUN_NATIVE=path to .node)
import x from "ghidra:./a.exe";                              // namespace form
```

`ghidraPlugin(opts)` is a `BunPlugin` (`onStart` clears the cache, `onResolve` maps `?ghidra`/`ghidra:` to namespace `ghidra`, `onLoad` returns a JS module; with `deferAnalysis` and `Bun.build` it awaits `defer()` first). Bun's documented hooks are `onStart/onResolve/onLoad/onBeforeParse` (bun.com/docs/runtime/plugins); there is no `onEnd`.

## Native plugin (`system/ghidra-bun`)

Crate `aphrody-ghidra-bun` (cdylib, `bun-native-plugin` 0.2.0 + `napi` 3.16.2). Standalone workspace; root `Cargo.toml` member line: `"system/ghidra-bun",`. Build on fr1: `cargo build --release` in `system/ghidra-bun` (feature `decompile` adds ghidra-decompiler C output). Copy the cdylib (`libaphrody_ghidra_bun.so`, `libaphrody_ghidra_bun.dylib` or `aphrody_ghidra_bun.dll`) to `aphrody_ghidra_bun.node`. The crate stays on edition 2021 until it is promoted to the root workspace (edition 2024).

```ts
import { nativeGhidraPlugin } from "@aphrody/ghidra/plugin";
await Bun.build({ entrypoints: ["app.ts"], plugins: [nativeGhidraPlugin("./aphrody_ghidra_bun.node")] });
// app.ts: import report, { functions } from "./target.ghidra.js"  (stub text = path of the binary, or empty to use target)
```

The addon also exports `analyze(path, maxFunctions)` and `version()`. `onBeforeParse` runs in `Bun.build` only (Bun's runtime plugins do not support it). Proof: `scripts/native-proof.ts`.
